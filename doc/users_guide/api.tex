\chapter{Programming Interface Overview}
\label{api}

The CoastWatch software includes a Java programming interface that can be
used to access data files, perform analysis, and generate visualizations.
This chapter provides a conceptual overview of the CoastWatch
programming interface and is not intended to replace the generated
Javadoc reference.

The API evolves between software releases as new functionality is added.
For this reason, detailed and version-specific documentation is provided
in the generated Javadoc and example source code distributed with the
software. This chapter focuses on stable concepts, core entry points,
and common usage patterns.

\section{Intended Audience}

This chapter is intended for:
\begin{itemize}
  \item Developers interested in using the CoastWatch Utilities as a Java
        library.
  \item Advanced users writing or modifying BeanShell scripts.
  \item Users who want to understand how the graphical tools relate to
        the underlying code.
\end{itemize}

It is not necessary to read this chapter to use the graphical tools or
command-line utilities.

\section{API Documentation and Examples}

The complete Java API reference is provided as generated Javadoc
documentation. This documentation should be treated as the authoritative
and up-to-date reference for all classes, methods, and interfaces.

The following files are included with the software distribution:
\begin{itemize}
  \item \file{lib/java/cwutils.jar} --- the main Java library.
  \item \file{lib/java/depend/*.jar} --- the Java dependencies.
  \item \file{lib/java/native} --- the native dependencies.
  \item \file{doc/api.zip} --- generated Javadoc documentation.
  \item \file{src.zip} --- source code and utility implementations.
\end{itemize}

Developers are encouraged to rely on the Javadoc search and package
summaries when exploring the API.

\section{Core Concepts}

Rather than documenting individual classes, this section describes the
main concepts that organize the CoastWatch Java API.

\subsection{Reading Data}

Data access in the API is centered around the concept of a data reader.
A reader is responsible for opening a data file, exposing its variables,
and providing access to metadata.

Most applications begin by using a factory class to create an appropriate
reader for a given file. Readers typically provide:
\begin{itemize}
  \item A list of available variables.
  \item Metadata describing the dataset and variables.
  \item Methods for reading data values.
\end{itemize}

\subsection{Variables and Data Types}

Variables represent individual data fields within a dataset. Many
variables correspond to two-dimensional gridded data, while others may
represent lines, tracks, or scalar values.

Variables are typically accessed by name and may carry associated
attributes such as units, scaling information, and quality flags.

\subsection{Rendering and Visualization}

The visualization portion of the API converts data variables into
graphical representations. Rendering is conceptually separated into:
\begin{itemize}
  \item Data views that map values to colors.
  \item Color palettes and enhancement functions.
  \item Optional compositing of multiple variables.
\end{itemize}

These components are the same ones used internally by the CDAT
application. As a result, scripted or programmatic visualizations
closely match those produced interactively.

\subsection{Overlays and Annotations}

Overlays add contextual graphics such as coastlines, grids, legends,
and annotations to a rendered view. Overlays are layered on top of the
data image and do not modify the underlying data.

Overlay classes are typically independent of the data source and can
be reused across different datasets.

\section{Common Usage Patterns}

The following patterns illustrate typical ways the API is used. Exact
class and method names may vary by release; consult the Javadoc for
details.

\begin{itemize}
  \item \textbf{Listing variables in a data file} --
        Open a file using a reader and query its variable list.
  \item \textbf{Generating a quicklook image} --
        Select a variable, create a data view, apply enhancement and
        palette settings, and render an image.
  \item \textbf{Adding geographic context} --
        Attach overlays such as coastlines or grids to a view prior
        to rendering.
\end{itemize}

Many of these patterns can be found implemented in the example source
code included with the software.

\section{BeanShell Scripting}

The CoastWatch software supports BeanShell scripting for automation and
custom analysis via the cwscript tool. BeanShell scripts operate directly on the same Java
classes used by the graphical tools.

Most BeanShell scripts follow the same conceptual steps as Java programs:
open a dataset, select variables, perform analysis or visualization,
and write results to disk.

Scripts found in the cwscript manual page provide working examples that can
be modified for custom workflows.

\section{Relationship to Command-Line Tools}

The command-line utilities included with the CoastWatch software are
themselves implemented using the Java API described in this chapter.

Developers can think of the API as the foundation layer, with graphical
and command-line tools built on top. Studying utility source code is
often the fastest way to understand how a particular operation is
performed programmatically.

\section*{Final Notes}

The CoastWatch Java API is a powerful but specialized interface. Most
users will never need to interact with it directly. For those who do,
the combination of this chapter, the generated Javadoc, and the example
source code provides a complete picture of how the system is organized.
