\chapter{The CoastWatch Data Analysis Tool (CDAT)}
\label{cdatchap}
\hypertarget{cdatchap}{}

The CoastWatch Data Analysis Tool (CDAT) is an interactive application for
visualizing, exploring, and analyzing gridded Earth science data.
It's designed around a modern map-viewer paradigm, combining layered
geospatial visualization with interactive data controls.

\section{Interface Overview}

\autoref{cdat_components} shows the major components of the CDAT
interface.  The application is organized around a central data view,
surrounded by controls for data selection, visualization, and analysis.

\begin{figure}
  \begin{center}
    \myfigure{cdat_components}
    \caption{Major components of the CDAT interface}
    \label{cdat_components}
  \end{center}
\end{figure}

The interface consists of the following high-level regions:
\begin{itemize}
  \item \textbf{Menu bar and tool bar} -- Access to file operations, tools,
        and application-wide commands.
  \item \textbf{File tabs} -- Each open dataset is displayed in its own tab,
        allowing multiple files to be compared within a single session.
  \item \textbf{Data view and navigation} -- The central map display showing the currently
        selected variable, visualization settings, and navigation buttons.
  \item \textbf{Control tabs} -- Panels for adjusting visualization,
        overlays, annotations, surveys, and composites.
\end{itemize}

This chapter introduces the main interface concepts and workflows.
Individual tools are designed to be discoverable through direct use and
contextual help within the application.

\section{Opening Data Files}

Data files are opened using the {\gui File \(\rightarrow\) Open} command
or the corresponding toolbar button.  CDAT supports a variety of
NetCDF and HDF-based Earth science data formats.

\begin{figure}
  \begin{center}
    \myfigure{file_open}
    \caption[File open dialog]{
       File open dialog showing file list, variable selection,
       and data preview
    }
    \label{file_open}
  \end{center}
\end{figure}

When opening a file (\autoref{file_open}), the user selects a dataset
and one or more variables to load into the session. The file open dialog provides:
\begin{itemize}
  \item \textbf{File list} -- Selection of a data file from the local file system.
  \item \textbf{Variable list} -- One or more variables to load from the file.
  \item \textbf{Data preview} -- A preview image and metadata summary for the
        currently highlighted file and variable.
\end{itemize}
If multiple variables are selected, they are all loaded into the file tab.
One variable is chosen as the initial display variable, while the remaining 
variables are available through the variable selector in the main interface.

\section{Navigating the Data View}

CDAT displays two-dimensional geographic data using a map-based view,
with north oriented upward. Navigation is designed to behave similarly
to modern interactive map viewers.

Users can navigate the data view using the on-screen navigation controls
that appear within the view, as well as standard mouse and trackpad
gestures.

Common navigation actions include:
\begin{itemize}
  \item \textbf{Zooming} -- Zoom in and out to examine data at different
        spatial scales.
  \item \textbf{Panning} -- Move the view to explore different regions of
        the dataset.
  \item \textbf{Resetting the view} -- Return to an overview showing the
        full data extent.
\end{itemize}

Navigation controls are located directly within the data view to keep
interaction focused on the data itself. Equivalent navigation commands
are also available through the {\gui View} menu.

\section{Data Visualization}

Visualization controls are grouped into tabs on the right-hand side of the
interface.  Each tab corresponds to a specific visualization task.

\subsection{Enhancement}

The Enhancement tab controls how raw data values are mapped to color.
\autoref{enhancement_tab} shows the enhancement controls.

\begin{figure}
  \begin{center}
    \myfigure{enhancement_tab}
    \caption{Enhancement controls}
    \label{enhancement_tab}
  \end{center}
\end{figure}

The enhancement controls include:
\begin{itemize}
  \item \textbf{Histogram} -- Displays the distribution of data values.
  \item \textbf{Enhancement range} -- Minimum and maximum data values mapped
        into the active palette.
  \item \textbf{Enhancement function} -- The mathematical mapping applied
        within the selected range.
\end{itemize}

Adjusting the enhancement range and function allows subtle data features
to be emphasized without altering the underlying data.

\subsubsection*{Choosing an enhancement function}

Different enhancement functions are useful for different data
characteristics:

\begin{itemize}
  \item \textbf{Linear} -- Appropriate for most geophysical variables
        where equal changes in data value should appear as equal
        changes in color.
  \item \textbf{Logarithmic} -- Useful when data values span several
        orders of magnitude, such as chlorophyll concentration or
        aerosol optical depth.
  \item \textbf{Stepped} -- Emphasizes discrete value ranges and is
        useful for classification-style variables.
  \item \textbf{Gamma} -- Intended for brightness or reflectance data
        where perceptual contrast near dark or bright values is
        important.
\end{itemize}

\subsection{Palettes}

Color palettes determine how enhanced data values are displayed.

\begin{figure}

The Palette tab (\autoref{palette_tab}) allows users to:

  \item Maintain a list of favorite palettes for quick access.

\subsection{Color Composites}

CDAT supports RGB color composites constructed from multiple variables.

\begin{figure}
  \begin{center}
    \myfigure{composite_tab}
    \caption{Composite variable selection}
    \label{composite_tab}
  \end{center}
\end{figure}

In composite mode:
\begin{itemize}
  \item A separate variable is selected for each color channel
        (red, green, and blue).
  \item Enhancement settings are applied independently to each channel.
\end{itemize}

Composite mode is useful for combining related variables into a single
visualization.  This allows multiple
physical properties to be visualized in a single image.

Unlike single-variable displays, RGB composites emphasize relative
differences between variables rather than absolute values. The choice
of variables and their individual enhancement settings strongly affects
the visual outcome.

\subsubsection*{Interpreting RGB Composites}

In an RGB composite:
\begin{itemize}
  \item Bright or saturated colors indicate dominance of one or more
        channels.
  \item Neutral or gray tones indicate similar values across channels.
  \item Color boundaries often reveal transitions or gradients between
        physical regimes.
\end{itemize}

Because each channel is enhanced independently, composites should be
interpreted qualitatively rather than as precise quantitative displays.

\subsubsection*{Example Composite Configurations}

The following examples illustrate common ways RGB composites are used.
They are intended as starting points rather than fixed recipes.
\begin{itemize}
  \item \textbf{True-color style composites} --
        Visible or reflectance channels mapped to red, green, and blue
        to approximate natural-color imagery.
  \item \textbf{Ocean color composites} --
        Chlorophyll concentration, turbidity, or reflectance bands
        combined to highlight biological and coastal features.
  \item \textbf{Thermal composites} --
        Multiple infrared channels combined to emphasize temperature
        structure, clouds, or atmospheric effects.
\end{itemize}

\subsubsection*{Enhancement Considerations}

Each RGB channel has its own enhancement range and function. Small
adjustments to enhancement often have a larger visual impact than
changing the variables themselves.

For this reason, developing effective RGB composites is typically an
iterative process involving both variable selection and enhancement
tuning.

More detailed RGB composite examples and guided demonstrations are
available in the online tutorial course accessible via
{\gui Help \(\rightarrow\) Open Online Tutorial Course}.

\section{Overlays, Surveys, and Annotations}

Vector overlays, annotations, and surveys are displayed as layers on top
of the data view.

\subsection{Overlays}

\begin{figure}
  \begin{center}
    \myfigure{overlays_tab}
    \caption{Overlay management}
    \label{overlays_tab}
  \end{center}
\end{figure}

Overlays (see \autoref{overlays_tab}) include geographic boundaries, grids, and thematic layers.
Users can control visibility, styling, and layer order.

\subsubsection*{Overlay Data Sources}

Many built-in overlays are derived from widely used geospatial
reference datasets. For example, coastlines and political boundaries
are rendered from global shoreline and boundary databases, while
topographic and bathymetric overlays are derived from gridded elevation
models.  

Overlay resolution adapts automatically to the current zoom level,
providing higher detail when viewing smaller regions.

\subsubsection*{Mask Overlays}

Mask overlays are used to visually suppress or highlight data values
based on quality flags or logical conditions. Common uses include
masking clouds, land, or other invalid data regions.

Masks may be derived from:
\begin{itemize}
  \item \textbf{Bit flags} stored in quality or mask variables, or
  \item \textbf{Logical expressions} involving one or more variables.
\end{itemize}

Masking affects visualization only and does not alter data values.

\subsubsection*{Overlay Groups}

Overlay groups allow frequently used sets of overlays to be saved and
restored as a single configuration. This is useful when switching
between different analysis contexts, such as atmospheric versus
oceanographic data.

Default overlay groups are provided, and users may create custom groups
tailored to their workflows.

\subsection{Surveys}

\begin{figure}
  \begin{center}
    \myfigure{surveys_tab}

  \end{center}
\end{figure}

Surveys (see \autoref{surveys_tab}) allow data values to be sampled along user-defined paths or areas.
Statistical summaries and plots are displayed for each survey.

\subsubsection*{Survey Types and Results}

Surveys allow quantitative inspection of data values at specific
locations or regions. CDAT supports point, line, and area-based
surveys.

Survey results may include summary statistics and plots showing how
data values vary spatially. Surveys are intended for exploratory
analysis and comparison rather than bulk data extraction.

\section{Exporting Images and Data}

CDAT can export the current view in one of two ways as:
\begin{itemize}

  \item \textbf{Color images} for use in creating website graphics,
  printable materials, or presentation slides, or

  \item \textbf{Numerical data formats} for use in external applications
  such as GIS or custom data processing.

\end{itemize}
Export options are available from the toolbar and the {\gui File} menu.

Exports reflect the current visualization settings, including
enhancement, palette, overlays, and annotations.  Details on the supported 
color image or numercial data export formats are given in \autoref{output_formats} and
\autoref{format_specs}.

\section{Navigation Analysis}

CDAT includes tools for analyzing geographic navigation accuracy in
data products, accessed from the menu bar via {\gui Tools \(\rightarrow\) Navigation Analysis}. 
These tools are intended for specialized diagnostic use
and complement command-line navigation utilities included with the
CoastWatch software.

\subsection*{Custom Palettes and the Resources Directory}

CDAT supports user-defined color palettes in addition to the palettes
installed with the software. Custom palettes are stored in the
\emph{user resources directory}, which can be opened from the menu bar
via {\gui Tools \(\rightarrow\) Preferences \(\rightarrow\) Open User Resources Directory}.

The resources directory contains user-editable configuration files
such as color palettes, preferences, and other auxiliary data.
Advanced users may inspect or modify these files directly, for example
to add new palettes or share visualization settings across systems.

Custom palettes use a simple XML format. Once added to the resources
directory, palettes become available automatically within CDAT.  
See \autoref{palette_xml} for format details.

\section{Using CDAT and command-line tools together}

CDAT and the CoastWatch command-line tools provide complementary ways of working
with the same underlying data formats, metadata, and processing operations.
CDAT is optimized for interactive exploration and visualization, while the
command-line tools are designed for repeatable, automated, and large-scale
processing.

Many users naturally combine the two approaches in a single workflow. CDAT is
often used first to inspect data, explore variables, experiment with regions or
processing parameters, and understand the structure of a dataset. Once those
choices are established, the corresponding command-line tools can be used to
apply the same operations consistently across many files or as part of scripted
pipelines.  When a desired operation is visually obvious in CDAT but needs to 
be performed programmatically or at scale, \autoref{common} provides guidance 
on selecting the appropriate command-line tools.

Common examples of this combined workflow include:
\begin{itemize}
  \item \textbf{Inspecting and diagnosing data} -- Interactive examination of
  variables, metadata, and value ranges in CDAT, followed by scripted summaries
  or checks using command-line tools.
  \item \textbf{Subsetting and preparation} -- Visual selection of regions,
  variables, or time ranges in CDAT, followed by automated extraction or format
  conversion on the command line.
  \item \textbf{Generating derived products} -- Exploratory experimentation in
  CDAT to determine suitable processing steps, followed by batch computation
  using command-line tools.
  \item \textbf{Rendering graphics} -- Interactive refinement of display settings
  in CDAT, followed by automated rendering for production or publication.
\end{itemize}

This guide does not attempt to document a one-to-one correspondence between CDAT
interface elements and specific command-line options. The CDAT interface and the
command-line tools evolve independently, and detailed mappings would be brittle
over time. Instead, users are encouraged to treat CDAT as a discovery and
exploration environment, and the command-line tools as the authoritative
mechanism for reproducible and automated processing.

Detailed documentation for individual command-line tools, along with shared
runtime behavior and execution conventions, is provided in \autoref{manual}.
